## Windows 单文件 exe

Windows x64 的发行形态是自包含的 `Nowluma.exe`：

- 由 `tools/build-windows-exe.mjs` 打包，内置 Node 与运行环境；不需要 Docker、Node 或 .NET 安装。
- 双击后解压到 `%LOCALAPPDATA%\Nowluma`，在浏览器打开控制台；可选择本机 QQ，或在已有 Linux Docker 时选择隔离桌面。
- 当前构建**未签名**，可能触发 SmartScreen；发行说明应给出 SHA-256，没有校验值的二进制不要直接运行。
- 关闭窗口可能提前结束进程；建议在控制台按 Ctrl+C 正常停止。QQ 用户数据和设置不会被删除。

这不是「已签名」或「已在真实账号上验收」的声明。真实 QQ 登录、注入与长期会话仍需要你自己验证；见 [原生安装](install-native.md#windows)。

## 性能模式

外观设置里的「性能模式」已经实现，是一个中性的显示选项：

- 「自动检测（默认）」只在前台持续低帧率时关闭动画和实时折射；检测结果不写回服务器，也不影响其他设备。
- 「完整效果」与「低性能 / 关闭动效」由你手动选择。
- 它不改变消息、账号或网络行为，不承诺帧率、省电或低端设备收益，也没有可引用的性能基准。

「自动挑账号、自动调整资源策略」仍只是方向，没有对应界面。不要把性能模式与「自动连接已打开的 QQ」混为一谈：后者是程序启动时尝试接入，**不是** QQ 自动登录。

## 六份原始预编译文件与双内核

- 仓库保留的六份 `nowluma-*` 原始预编译文件（三个平台各 `.node` 加 `.dll`/`.so`）是当前发行使用的原生组件；当前只改外部文件名，内部字节和必要的旧套接字 ABI 保持不变。
- 另有外部重写尝试，尚未完成、未随包发布；目前只观察到部分 Windows DLL 构建，`.node` 链接、真实注入、收发校准、登录行为和 Linux 配对都未在本仓库验证。
- 本轮不重写 QQ 接入内核。双内核选择器尚未实现；将来引入时，原内核需要用户主动知情并接受风险，所有 QQ 接入路径都不会预勾选或静默回退。

## 融合样式（fused styles）

玻璃与融合组件已经存在；当前界面正在结构性重构，视觉细节会继续变化。现有外观体系（调色板、强调色、背景、主题微调、自定义 CSS）仍按原优先级工作，见 [系统设置：控制台](settings-console.md#外观)。

这一轮没有做独立视觉验收，也不提供截图；本文档不写像素位置与具体颜色值。自定义 CSS 与「宿主接管外观」的优先级没有因融合样式改变。

## 模拟练习模式 `/demo/`

- 路径 `/demo/`，由站点构建生成（当次构建包含模拟器时）。
- 方案：用独立的模拟 API 层渲染真实界面，页面持续标注「模拟数据」。
- 不使用任何真实凭据，不向外部发请求。

**仍需你自己确认**：

1. 页面上有持久的「模拟」标记，且不提供真实的令牌/密码输入。
2. 它不会把模拟结果写进任何真实配置文件。

## 发行与发布流水线

- 自动化流水线正在扩充，本文档不描述「已经有哪些工作流」之外的细节。
- 已知会产出的形态：Linux 平台发行包的 Lite 变体、Windows x64 的 `Nowluma.exe` 单文件，以及本地构建的 Docker 镜像（`docker build -f deploy/docker/Dockerfile`）。
- `deploy/install.sh` 只在源码仓库里，不随 Lite 或 Windows 发行包分发。
- 未配置：npm 发布、镜像仓库发布、跨仓库自动发布。
- 因此：不要声称存在官方镜像仓库标签、签名安装包或不存在的发行文件。

## 阅读时的判断规则

看到任何一条描述，如果它属于下面几类，请先假设它「尚未验证」：

- 带「保证」「一定」「永不」的结论。
- 声称某个平台「已测试」但没给出测试方式。
- 提供下载地址但没有校验值。
- 展示截图但没有标注版本。

本文档体系里，凡是这类内容都会显式标注状态，而不是混在操作步骤里。
