## Windows 发行形态

现状与建议：

1. 安装脚本检测到非 Linux 会退出，并提示使用 Windows 的一键运行方式。
2. 根 README 提到双击 `launcher.bat`。
3. 是否存在已发布的单文件 exe、叫什么名字、是否有代码签名，**目前没有验证记录**。

因此文档只描述「Windows 上的使用形态应当是什么」（[原生安装](install-native.md#windows)），不提供下载地址、不写产物名、不承诺签名。等发布方确认后，这一节会被替换成事实描述。

**给读者的判断方法**：如果你拿到的发行包里只有一个可执行文件而没有任何说明，先确认它来自你信任的来源，并核对发布说明里给出的校验值。没有校验值的二进制不要直接运行。

## Auto / 性能界面

这一类功能的方向是：把「自动选择、自动调整」的界面能力做成可选模式，例如自动挑账号、自动套用更省资源的显示策略。

现在的状态：

- **没有**可点击的开关、没有对应的设置分组。
- 文档不描述具体控件，因为描述了就会变成「看起来已经存在」。

**集成待办（给实现方）**：功能落地后需要同步补充：

1. 它出现在哪个页面（总览？系统设置？新增页签？）。
2. 开关的默认值、保存位置、是否需要重启。
3. 关闭后行为如何回退。
4. 与「自动连接已打开的 QQ」的关系——后者的语义是「程序启动时尝试接入」，**不是** QQ 自动登录，两者不要混称。

## 融合样式（fused styles）

视觉上把多个界面元素合并成一体观感的样式方案。当前状态：

- 尚无实现，也没有截图可引用。
- 现有外观体系（调色板、强调色、背景、主题微调、自定义 CSS）是**已实现**的，见 [系统设置：控制台](settings-console.md#外观)。
- 视觉细节仍在调整中，本文档刻意不写像素位置与具体颜色值。

**集成待办**：样式落地后需要更新外观一章的控件清单，并检查「自定义 CSS」与「宿主接管外观」是否仍然按现有优先级工作。

## 模拟练习模式 `/demo/`

- 路径预留为 `/demo/`。
- 方案：用独立的模拟 API 层渲染真实界面，页面持续标注「模拟数据」。
- 不使用任何真实凭据，不向外部发请求。
- 页面外壳由发布方的站点生成器负责，文档只提供内容与边界说明。

**集成待办**：

1. 站点接入 `/demo/`，并在导航里出现入口。
2. 从本页与 [模拟练习模式](demo.md) 链接过去。
3. 确认页面上有持久的「模拟」标记，且不提供真实的令牌/密码输入。
4. 确认它不会把模拟结果写进任何真实配置文件。

## 发行与发布流水线

- 自动化流水线正在扩充，本文档不描述「已经有哪些工作流」之外的细节。
- 已知会产出的形态：Linux 平台发行包的 Lite 变体；Docker 镜像由本地构建（`docker build -f deploy/docker/Dockerfile`）。

- 因此：不要声称存在官方镜像仓库标签、签名安装包或不存在的发行文件。

## 阅读时的判断规则

看到任何一条描述，如果它属于下面几类，请先假设它「尚未验证」：

- 带「保证」「一定」「永不」的结论。
- 声称某个平台「已测试」但没给出测试方式。
- 提供下载地址但没有校验值。
- 展示截图但没有标注版本。

本文档体系里，凡是这类内容都会显式标注状态，而不是混在操作步骤里。
