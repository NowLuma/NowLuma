# 首次启动

这一章覆盖「打开浏览器之后、看到总览之前」的全部界面。控制台首次启动时按固定顺序要求几件事：登录 → 协议确认（如果需要）→ 设置访问密码（如果需要）。

## 三个不要混淆的凭据

| 凭据 | 用在哪里 | 谁能重置 |
| --- | --- | --- |
| 控制台访问密码 | 登录这个浏览器控制台 | 你在服务器上操作，见本文末尾的恢复步骤 |
| 双重验证（2FA）验证码 | 登录第二步 | 恢复码；或用密码 + 恢复码重新绑定 |
| OneBot 授权令牌 | 机器人程序连接端点时填写 | 在「节点配置」里重新生成，**和登录控制台无关** |

QQ 密码不在这张表里：程序从不向你要 QQ 密码，也从不保存它。

## 1. 启动画面

打开地址后先看到「初始化中…」和骨架屏。这一步只是等待前端与会话状态就绪。

**预期结果**：几秒内进入登录页或直接进入总览（浏览器里已有有效会话时）。

**一直停在这里怎么办**：检查控制台进程是否在运行（Docker 用 `bash deploy/manage.sh doctor`）、地址端口是否正确、反向代理是否保留了 `/api/` 路径。见 [排障与失败恢复](troubleshooting.md)。

## 2. 登录页

页面副标题是「OneBot v11 协议网关 · 安全登录」，下面只有一个输入框，占位文字「输入访问令牌」。

这个输入框要填的是**控制台访问密码**，不是 OneBot 令牌，也不是 QQ 密码。名字容易误解，但行为只有一种：验证通过就进控制台。

| 控件 | 作用 |
| --- | --- |
| 密码输入框 | 输入访问密码 |
| 「显示密码」/「隐藏密码」 | 切换明文显示 |
| 提交按钮 | 提交；密码错误会显示错误横幅并抖动提示 |
| 「界面有点卡顿？」 | 打开一个小弹窗，可关闭登录页的动态背景，纯本地开关 |

登录页的主题来自未登录状态也能读的公开外观接口，因此你之前设的主题色在登录前就会生效；自定义 CSS 不在其中，登录页不会被它影响。

### 用链接一次性登录

URL 里带 `?token=<访问密码>` 时，页面会立即消费这个令牌完成登录，然后把它从地址栏移除。令牌用过一次就失效，不会留在历史记录里。

如果需要第二步验证，密码会被带进验证码步骤，你只需要再输入一次验证码。

**注意**：这条路只适合一次性设备。不要把带密码的地址发到聊天记录、工单或截图里。

### 双重验证（2FA）

开启过 2FA 的账号会看到第二步：

| 控件 | 作用 |
| --- | --- |
| 6 位验证码 | 从你的验证器应用读取 |
| 「使用恢复码」 | 切换到 8 位字母数字恢复码输入 |
| 「改用验证码」 | 切回 6 位验证码 |
| 「返回」 | 回到密码步骤 |

验证码可以粘贴到任意一格，会自动分配到六格。恢复码一次性使用，用掉的恢复码在「账号安全」里会显示剩余数量。

**预期结果**：通过后进入引导或总览。

**失败怎么办**：验证码依赖本机时间，先确认设备时间同步；恢复码也用完时，按 [系统设置：控制台](settings-console.md#双重验证) 的说明在已登录设备上重新生成，或按本文末尾的恢复步骤处理。

## 3. 协议状态加载失败

如果连协议状态都读不到，整个控制台会被一个错误页替代：

- 标题「协议状态加载失败」。
- 按钮「重新加载」和「退出登录」。

页面明确说明协议确认不能跳过。这是有意为之：读不到协议版本就无法确认你是否已经同意。

**处理顺序**：点「重新加载」→ 检查服务端是否健康 → 确认反向代理没有拦截 `/api/agreements` → 仍失败则看服务端日志。

## 4. 首次使用设置（引导）

需要时会出现「完成首次使用设置」向导，副标题「按顺序完成必要步骤后即可进入控制台。」

步骤顺序由服务端下发的两个标记决定：

1. `needsConsent` 为真时，第一步是「阅读并同意协议」。
2. `mustChangePassword` 为真时，下一步是「设置访问密码」。

两个都不需要时，直接进入控制台。服务端已经应用了环境变量策略（例如接受法律条款的环境标记会跳过协议步骤）。

### 4.1 阅读并同意协议

- 标题「请阅读并同意以下协议」，下面是可滚动的协议正文。
- 说明文字：「同意一次后无需重复确认；仅当协议内容更新时才会再次请求确认。」
- 复选框：「我已阅读并同意《用户协议》与《隐私政策》」。
- 按钮：「不同意并退出」（会登出）、「同意并继续」（提交时显示「提交中…」）。

**示例**：勾选复选框 → 点「同意并继续」→ 预期进入下一步或总览。协议版本变化后再登录，这一步会重新出现。

### 4.2 设置访问密码

- 标题「设置访问密码」，输入时逐条显示强度规则。
- 规则：长度不少于 10 位、包含小写字母、包含大写字母、包含特殊符号（如 `!@#$%`）、不包含空格。
- 提交按钮「保存并完成」。

密码以加盐 scrypt 哈希保存在程序配置目录的 `webui.json` 里，不保存明文。保存后其他设备上的旧会话会立即失效。

**示例**：`EXAMPLE-Aa1!` 满足全部规则（它只是排版示例，不要照抄）；点「保存并完成」→ 预期向导关闭并进入「总览」。

**失败怎么办**：规则条实时提示哪一条没满足；提交失败时保留在对话框内并显示错误，不会静默通过。

### 4.3 向导的脚注

底部有「上一步」「下一步」「完成」「跳过」，可以按需回看已完成的步骤。「跳过」只在没有强制步骤时可用。

## 5. 登录之后先看什么

进入控制台后建议按这个顺序：

1. [总览](overview.md) 的引导面板会列出当前缺哪一步。
2. 点「打开 QQ 桌面」，在里面的 QQ 窗口扫码登录，并在 QQ 自己的设置里勾选自动登录。
3. 回 [QQ 连接](qq-connection.md) 加载账号。
4. 需要机器人业务时再去 [节点配置](onebot-config.md)。

## 6. 安全提示横幅

用非回环地址、且协议不是 HTTPS 时，页面顶部会出现不安全访问提示。它不会阻止你使用，但含义是：密码和会话会在网络上以明文传输。

处理方式：改用 SSH 隧道、配置 TLS，或把绑定地址改回仅本机。见 [访问方式与网络](access-network.md)。

## 7. 忘记密码或丢失 2FA

以下操作都在服务器本机执行，需要文件系统权限。先备份，再动手。

1. 停止服务：`bash deploy/manage.sh stop`（原生运行则结束程序进程）。
2. 备份配置目录：`cp -a config config.backup-$(date +%F)`。
3. 删除（或改名）`config/webui.json`。
4. 启动服务：`bash deploy/manage.sh start`。
5. 在启动日志里找到新的初始密码：`bash deploy/manage.sh logs`，搜索 `initial credentials`。

也可以先把环境变量 `NOWLUMA_WEBUI_BOOTSTRAP_PASSWORD` 设成你要的临时密码，再启动；它只在没有 `webui.json` 时生效。

**代价必须说清楚**：这个文件同时保存访问密码哈希和 2FA 绑定。删掉它意味着旧的 2FA 也一并失效，需要重新绑定；同时所有已登录会话都会失效。这就是为什么第 2 步要先备份。

如果只是 2FA 设备丢了、密码还记得，不需要删文件：用恢复码登录，或在「系统设置 → 账号安全」里重新生成恢复码/关闭 2FA。

## 8. 保存与重启语义小结

| 操作 | 保存位置 | 何时生效 | 是否需要重启 |
| --- | --- | --- | --- |
| 协议确认 | 程序配置目录 | 立即，且长期有效（版本变化后重问） | 否 |
| 修改访问密码 | `webui.json` | 立即；其他设备会话失效 | 否 |
| 开启 / 关闭 2FA | `webui.json` | 立即 | 否 |
| 退出登录 | 服务端会话 | 立即 | 否 |
