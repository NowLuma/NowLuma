# 首次启动

先从安装输出或启动日志中找到初始访问密码。想先练习时，点 **加载模拟器** 并使用练习中给出的凭据。

![首次设置中的说明阅读与确认页面](/images/tutorials/first-run.png)

首次打开时先验证控制台访问密码，再完成使用说明、访问密码、显示效果和账号内核四步设置。整个过程在浏览器中完成。

设置过程的进度和错误会显示在对应步骤内。

## 启动画面

页面中央显示「初始化中…」和骨架占位，表示正在检查本地会话与后端状态。

如果一直停在这里：确认服务已启动（Docker 用 `bash deploy/manage.sh logs`），端口没有被占用，反向代理保留了 `/api/`。见[排障与失败恢复](troubleshooting.md)。

## 登录

在「进入工作台」页面填写 Nowluma 的初始「访问密码」，然后点「打开工作台」。完成设置后改用你选的新密码；QQ 凭据请在 QQ 窗口输入。

## 双重验证

开启 2FA 后，密码验证通过还要输入一次性验证码：

| 控件           | 用法                                                         |
| -------------- | ------------------------------------------------------------ |
| 「验证码」     | 输入 Authenticator 中的 6 位验证码，可以整段粘贴到任意一格   |
| 「使用恢复码」 | 切换到恢复码输入；连字符会自动忽略                           |
| 「改用验证码」 | 从恢复码切回 6 位验证码                                      |
| 「恢复码」     | 每个恢复码只能用一次；剩余数量在偏好设置的「账号安全」里查看 |

验证码或恢复码错误时，页面会提示「验证码不正确，改错的那一位即可。」或「恢复码不正确，改错的那一位即可。」，不会清空其他已填内容。

## 用链接登录

在控制台地址后加 `?token=<访问密码>` 可跳过手动输入密码。控制台会在尝试登录前从地址栏移除该参数；开启双重验证时仍需输入验证码。不要分享含密码的链接，远程访问请用 [SSH 隧道或 HTTPS](access-network.md)。

## 阅读与设置密码

登录后进入「完成首次使用设置」。步骤依次为「阅读使用说明」「设置访问密码」「显示效果」「选择接入内核」。

「选择接入内核」是接入前的额外一步：可以为检测到的 QQ 账号保存内核选择，检测不到账号时点「继续」即可往下走，等 QQ 登录后再为该账号选择。

### 阅读使用说明

- 标题「阅读使用说明」，说明「阅读后确认，即可继续设置。」。
- 可以切换「说明文档」查看《使用说明》和《隐私说明》；每份文档显示「版本 / Version … · 生效 / Effective …」。
- 勾选「我已阅读《使用说明》和《隐私说明》」后，「确认并继续」才可用；底部显示「说明版本 …」。
- 「退出」会回到登录页，不写入确认。
- 如果说明文本加载失败，会显示「未能加载说明文本，请刷新页面重试。」；提交失败会显示「提交失败，请重试」或「网络错误，请重试」。

这里的确认是**阅读说明**，不是同意一份额外的商业条款；它不会改变 GPL 许可，也不会给你增加额外义务。

### 设置访问密码

- 标题「设置新的访问密码」，说明「设置用于打开控制台的密码。」。
- 刚登录成功的密码就是当前密码，页面不会再要你输入一次；只需填写「新密码」和「确认新密码」两次。
- 规则以页面为准：不少于 10 位，包含小写字母、大写字母、特殊符号，且不包含空格。
- 「保存并继续」成功后，其他设备上的旧会话立即失效；当前浏览器会自动使用轮换后的新会话，接着选择显示效果和账号内核，再进入工作台。
- 从偏好设置的「开发者 → 重新进入」进入时是演练模式，按钮变成「完成演练」，不会保存输入，也不会修改真实密码或说明确认记录。

### 显示效果

分别选择「动效：开启 / 关闭」与「玻璃材质：完整玻璃 / 磨砂玻璃」，再点「保存并继续」。两个选择初始均未选，预览立即生效，服务器确认保存后才进入下一步。

关闭动效保留静态玻璃；磨砂玻璃减少折射开销，但不改动效开关。系统减少动态、减少透明和高对比仍作为辅助约束生效。开发者演练仅预览，退出恢复原设置，不保存外观。

## 之后看到什么

1. 工作台的连接工作流提示你先打开 QQ 或登录。
2. 在「QQ 会话」里选择进程并点「加载」。
3. 该账号第一次接入时，会先弹出「选择接入内核」：选中「兼容内核」，再勾选风险确认，最后点「确认并接入」；详见 [QQ 会话](qq-connection.md)。
4. 接入成功后到「机器人连接」为这个账号添加 HTTP 或 WebSocket 端点。

需要打开图形 QQ 时，点「打开 QQ 桌面」（仅当服务器实际提供同源桌面时显示）。桌面复用当前控制台会话，不需要另填 VNC 密码；Windows 原生不显示该入口。

## 忘记密码或丢失 2FA

控制台只有一个本地账号，没有邮箱找回。只有在确实无法登录时才重置：这会移除 2FA 和现有会话，其他配置与 QQ HOME 不应改动。

**Docker 安装**的配置在命名卷中，不是仓库根目录的 `config/`。在安装目录停止服务，再用原 Compose 配置挂载同一个卷，保留原认证文件：

```bash
bash deploy/manage.sh stop
docker compose --env-file deploy/.env -f deploy/docker-compose.yml run --rm --no-deps \
  --user 1000:1000 --entrypoint bash nowluma -lc '
    set -eu
    cd /app/config
    backup="webui.json.recovery-$(date -u +%Y%m%dT%H%M%SZ)"
    test -f webui.json
    test ! -e "$backup"
    mv -- webui.json "$backup"
  '
bash deploy/manage.sh start
bash deploy/manage.sh logs
```

**原生运行**请先用 Ctrl+C 停止 Nowluma，在实际运行目录（含 `index.mjs`）中把 `config/webui.json` 改为一个尚不存在的备份名称，再按原方式启动。Windows exe 的运行目录在 `%LOCALAPPDATA%\Nowluma`；不要改下载目录里未使用的副本。

启动后按日志提示获取新的初始密码并完成首设。保留旧文件，回退时先停止服务，再恢复原名称；旧密码、2FA 与会话也会随原文件恢复。`NOWLUMA_WEBUI_BOOTSTRAP_PASSWORD` 仅在没有 `webui.json` 时提供初始密码，不能覆盖现有认证。

## 协议状态加载失败

「协议状态加载失败」表示控制台暂时无法核验说明确认记录，核验成功后才会放行。

- 点「重新加载」重试。
- 点「退出登录」回到登录页。
- 检查 `/api/agreements` 是否可达、反向代理是否改写路径、服务器时间是否正确。

## 保存与重启

| 动作          | 保存位置                           | 是否需要重启         |
| ------------- | ---------------------------------- | -------------------- |
| 阅读说明确认  | 服务端配置                         | 否                   |
| 修改访问密码  | `config/webui.json` 的 scrypt 哈希 | 否，其他会话立即失效；当前浏览器继续使用轮换后的会话 |
| 开启/关闭 2FA | `config/webui.json`                | 否                   |
| 退出登录      | 仅清除当前浏览器会话               | 否                   |
