# 节点配置（OneBot 端点）

「节点配置」页（`/config`）按账号管理两件事：这个账号的通用行为（历史同步、`#nl` 状态命令、通知选择），以及它对外提供的 OneBot 端点。

左侧是账号栏（「在线连接」，没有账号时显示「暂无在线会话」），右侧是选中账号的配置。**只有在线账号才会出现在左侧**——账号不在线时保存仍然成功，但会提示下次连接生效。

## 页头与保存状态

| 元素 | 说明 |
| --- | --- |
| 「OneBot 协议端点」 | 页面标题 |
| `UIN {selectedUin}` | 当前账号 |
| 保存状态芯片 | 见下方状态表 |
| 「新建 {服务类型}」 | 只在四个网络页签出现 |
| 「保存」 | 保存当前账号的配置 |

保存状态芯片的可能值：

| 芯片文字 | 含义 |
| --- | --- |
| 未保存 | 有改动还没保存 |
| 保存中 | 请求进行中 |
| 已保存并应用 | 已落盘，且运行中的端点已热重载 |
| 已保存，下次连接时应用 | 已落盘，账号不在线，连接时才生效 |
| 已保存，但热重载失败：{原因} | 已落盘，热重载出错，服务端尽力恢复了旧端点 |
| 保存失败：{原因} | 没有落盘 |
| 上一版本已保存，当前修改待保存 | 旧改动已成功，新改动还没提交 |

芯片在 3 秒后自动消失。切换账号时如果有未保存改动，会弹出「放弃未保存的修改？」；选「放弃并切换」会丢掉这些改动。

## 页签

页签顺序固定：通用设置、HTTP API、HTTP 客户端、WS 服务端、WS 客户端。每个网络页签后面有节点数量徽章，支持方向键、Home、End 切换，最后停留的页签会被记住。

| 页签 | 说明文字 | 节点称呼 | 默认新建内容 |
| --- | --- | --- | --- |
| HTTP API | 本地监听 HTTP 端口，OneBot 客户端发起请求 | HTTP API 服务 | `http-N`，`127.0.0.1:3000`，路径 `/`，WS/SSE 关闭，自动生成 32 字节令牌 |
| HTTP 客户端 | 主动向远端 URL POST 推送事件 | HTTP 推送客户端 | `httppost-N`，`http://127.0.0.1:5700` |
| WS 服务端 | 本地监听 WebSocket 端口，客户端建立持久连接 | WebSocket 服务 | `ws-N`，`127.0.0.1:3001`，角色 `Universal` |
| WS 客户端 | 主动连接到外部 WebSocket 服务器（reverse-ws） | WebSocket 反向客户端 | `wsclient-N`，`ws://127.0.0.1:8080/ws`，重连间隔 5000ms |

四个页签的说明区上方都有一句关键提示：地址复制不包含令牌，令牌要在机器人程序里另外填；**监听正常不等于机器人已经连接**。

## 通用设置

### 登录时补齐云端历史记录

- 开关文案：「登录时补齐云端历史记录」，副标题「下次账号登录或重启后生效」。
- 范围有明确上限：最多 3 个群 + 3 个好友，每个会话 20 条，间隔至少 2 秒。
- 它只补本地缺失的历史，**不会重放事件**，也不改变服务端的已读状态。
- 账号在线时改这个开关不会立刻补，等下次登录或重启。

### 内置状态命令 `#nl`

| 控件 | 说明 |
| --- | --- |
| 开关 | 关闭后程序不再回复 `#nl`；下游机器人自己的回复逻辑不受影响 |
| 「触发词」 | 最多 32 字，保存时去掉首尾空格并转小写；默认 `#nl` |
| 「不转发给下游（swallow）」 | 打开后，命中触发词的消息不再转发给机器人，避免两边都回 |
| 「回复冷却（秒）」 | `0` 表示不限制 |

**示例**：发送纯文本 `#nl`，预期收到一条包含版本、平台、运行时长的回复。把触发词改成 `#status` 后保存，再发 `#nl` 不会响应，发 `#status` 才会。

### 通知选择（opt-in）

「通用设置」里的通知选择控制**这个账号**是否触发通知渠道：

- 折叠状态显示已选数量的摘要，展开后是可搜索的渠道列表。
- 「全选」只勾选已启用的渠道，不会把停用的渠道一起打开。
- 渠道本身的创建、Webhook/邮件字段、测试发送在 [系统设置：Nowluma 与平台](settings-runtime.md#通知) 里。

**保存语义**：通用设置的改动有 500ms 防抖，停止输入后自动保存，不需要点「保存」；网络节点的任何改动（新建、编辑、删除、启停）都立即保存。

## 节点卡片

每个节点在列表里显示为一张摘要卡：

| 元素 | 说明 |
| --- | --- |
| 名称 | 重复时打「名称重复」标签；停用时打「已停用」 |
| 状态芯片 | 正常 / 注意 / 异常 / 应用失败 / 未启用 |
| 摘要行 | 监听地址或目标地址 |
| 消息格式 | 「数组」或「CQ 码」 |
| 自身消息 | 「上报自身」或「不上报自身」 |
| 令牌 | 「已设 Token」或「无 Token」 |
| 「复制端点地址（不含凭据）」 | 只复制地址，不带令牌、用户名或查询参数 |
| 启用开关 / 编辑 / 删除 | 启停立即生效；删除立即移除该节点 |

空状态显示「暂无 {类型} 节点」和「创建第一个」。

## 节点对话框的每个字段

| 字段 | 出现位置 | 说明 |
| --- | --- | --- |
| 启用 | 全部 | 关闭后保存即停用 |
| 名称 | 全部 | 必填；与其他节点重名时提示「名称与其它节点重复」并不允许保存 |
| 授权 Token | 全部 | 可生成、可复制、可切换可见性；校验失败会就地给出策略提示 |
| 主机 | 入站（HTTP API / WS 服务端） | 监听地址；`0.0.0.0` 允许外部访问，需要配合防火墙 |
| 端口 | 入站 | 监听端口 |
| 路径 | 入站 | 例如 `/` 或 `/onebot` |
| 启用 WebSocket | HTTP API | 让同一个端口同时提供 WS |
| 启用 SSE | HTTP API | 让同一个端口提供 SSE 上报 |
| 消息格式 | 全部 | 「数组」= 标准 OneBot 消息段；「CQ 码」= 兼容字符串格式 |
| 角色 | WS 服务端 | `Universal` / `Event` / `Api`，决定这条连接接收/发送哪类帧 |
| 上报自身消息 | 全部 | `上报自身` 或 `不上报自身` |
| 目标 URL | 出站（HTTP 客户端 / WS 客户端） | 机器人程序提供的地址，不是控制台地址 |
| 超时 (ms) | HTTP 客户端 | 请求超时 |
| 重连间隔 (ms) | WS 客户端 | 断线后的重连间隔 |
| 单帧上限 (bytes) | WS 客户端 | 单帧最大长度，超过会被拒绝 |
| 取消 / 创建节点 / 保存修改 | 底部 | 「创建节点」用于新建，「保存修改」用于编辑 |

## 四种端点的例子

### 例 1：给本地机器人程序一个 HTTP API

1. 选账号 → 「HTTP API」→「新建 HTTP API 服务」。
2. 主机 `127.0.0.1`，端口 `3000`，路径 `/`，消息格式「数组」。
3. 点令牌旁的生成按钮，复制令牌。
4. 点「创建节点」。若账号在线，芯片会显示「已保存并应用」。
5. 在机器人程序里配置 `http://127.0.0.1:3000/` 和这个令牌。

**预期结果**：节点卡片状态为「正常」，总览「OneBot 连接」部件出现同名条目。机器人能调通动作，说明地址和令牌都对；这不代表它会自动回复群消息。

### 例 2：把事件推给自己的服务

1. 「HTTP 客户端」→ 新建。
2. 目标 URL 填 `http://127.0.0.1:5700`（示例），超时保持默认。
3. 保存并在自己的服务上打日志。

**预期结果**：你的服务收到 POST 请求。收不到时先看节点状态：如果是「异常」，是连接失败；如果是「正常」但没数据，检查对方的鉴权和路径。

### 例 3：让机器人反向连进来

1. 「WS 服务端」→ 新建。
2. 主机 `127.0.0.1`，端口 `3001`，角色 `Universal`。
3. 复制「复制端点地址（不含凭据）」，把令牌单独填进机器人程序。

**预期结果**：机器人在配置里连上后，卡片状态变为「正常」。如果对方一直重连，多半是令牌或路径填错。

### 例 4：主动连到机器人程序的 WebSocket

1. 「WS 客户端」→ 新建。
2. 目标 URL 填 `ws://127.0.0.1:8080/ws`，重连间隔 `5000`，单帧上限按对方文档设置。

**预期结果**：连接建立后状态「正常」；对方重启时会在重连间隔后自动重连。**这里填的是对方提供的地址**，不是控制台地址，也不是桌面地址。

## 令牌、地址与“监听正常”的区别

- 复制按钮只复制地址。令牌必须单独复制，目的是避免把凭据粘进聊天记录或截图。
- 每个端点有独立令牌；控制台访问密码不能代替 OneBot 令牌。
- 「正常」只表示端口在监听或连接已建立。机器人程序是否能正确处理动作、是否会回复消息，需要在机器人侧验证。
- 多账号共用监听服务时要给每个账号分配不同端口，并在部署侧发布对应端口。

## 保存、热重载与重启

| 情况 | 保存结果 | 生效时机 |
| --- | --- | --- |
| 账号在线 | `saved=true, applied=true` | 立即热重载，芯片「已保存并应用」 |
| 账号离线 | `saved=true, applied=false` | 账号下次连接时 |
| 热重载部分失败 | `saved=true, applied=false` + 每个端点的错误信息 | 旧端点被尽力恢复；按错误信息修配置再保存 |
| 校验失败 / 写入失败 | `saved=false` | 什么都没变 |

配置写在程序配置目录里，不需要重启程序就能对在线账号生效。**监听服务级别的改动**（控制台端口、绑定地址、TLS）不在这里，见 [系统设置：Nowluma 与平台](settings-runtime.md#服务)。

## 失败恢复

| 现象 | 处理 |
| --- | --- |
| 「名称与其它节点重复」 | 换一个名称；同一账号下名称必须唯一 |
| 芯片「已保存，但热重载失败」 | 读 `errors` 里的端点消息：端口被占用就换端口，绑定地址无效就换地址 |
| 机器人连不上 | 先确认节点状态不是「未启用」；再确认地址、端口、路径、令牌四项 |
| 改了令牌后旧机器人掉线 | 这是预期行为，令牌变了旧凭据就失效；把新令牌填进机器人程序 |
| 想临时停掉某个端点 | 用卡片的启用开关，不要删节点；删除只用于确认不再需要时 |
| 账号一直不在线 | 先解决 [QQ 连接](qq-connection.md)，配置本身没问题 |
