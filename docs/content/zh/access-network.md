# 访问方式与网络

这一章回答三个问题：从哪里访问控制台、怎么让它安全、桌面入口为什么和普通页面不一样。

## 三种访问方式

| 方式 | 适用 | 绑定地址 | 是否需要 TLS |
| --- | --- | --- | --- |
| 本机 / SSH 隧道 | 远程服务器（推荐） | `127.0.0.1` | 隧道已加密，可不配 |
| 局域网直连 | 同一内网、可信网络 | `0.0.0.0` | **建议**；否则密码明文传输 |
| 反向代理 + 域名 | 需要 HTTPS、单点入口 | `127.0.0.1` + 代理 | 必须 |

默认端口：控制台与桌面 **5099**、机器人 HTTP **3000**、机器人 WebSocket **3001**。

## SSH 隧道（最省事的安全方案）

在你自己电脑上执行：

```bash
ssh -L 5099:127.0.0.1:5099 -L 3001:127.0.0.1:3001 用户名@服务器地址
```

保持这个窗口打开，然后在浏览器访问 `http://127.0.0.1:5099`。

**预期结果**：就像访问本机服务一样；流量全程在 SSH 里加密，服务器不需要对外开放任何端口。

要在本机连机器人时，把 3000 也加上：

```bash
ssh -L 5099:127.0.0.1:5099 -L 3000:127.0.0.1:3000 -L 3001:127.0.0.1:3001 用户名@服务器地址
```

## 局域网

安装向导第二步可以选「2. 局域网」，它把绑定地址设成 `0.0.0.0`。控制台里也可以在「服务 → 服务监听 → 绑定地址」点「所有网卡」并保存（需要重启）。

代价必须明确：

- 任何能访问该端口的人都会看到登录页。
- 不配 TLS 时，访问密码在网络上明文传输。
- 选「所有网卡」时界面本身会警告：建议同时启用 HTTPS 并设置强访问凭据。

**不要把控制台和桌面入口直接暴露到公网。** 需要公网访问时用反向代理 + TLS。

## TLS 与反向代理

### 在控制台内启用 HTTPS

「服务 → HTTPS / TLS」里粘贴证书与私钥 PEM，点「保存证书」，打开「启用 HTTPS」，保存后重启服务。

- 证书无效会被拒绝。
- TLS 配置错误会让服务启动失败，不会静默降级成 HTTP。

### 用 Nginx 反向代理

先在该代理上配好 TLS。关键点：

```nginx
location / {
    proxy_pass http://127.0.0.1:5099;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 3600s;
    # 保留 X-Nowluma-Token；Authorization 可以留给代理做 Basic Auth
}

location /desktop/ {
    proxy_pass http://127.0.0.1:5099;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

规则：

- `Host` 必须保留真实的访问端口，否则来源判断会失准。
- `proxy_buffering off` 是 SSE（日志与状态推送）必需的，否则日志「实时」会变成批量到达。
- `/desktop/` 路径必须原样代理，WS 升级头必须透传，读超时要给足。
- 会话令牌走 `X-Nowluma-Token` 请求头，`Authorization` 留给代理自己的认证；后端也接受 `Authorization: Bearer`。
- `trustProxy` 只在**确定**请求来自你的代理时设置；无条件信任公网转发头等于放弃来源校验。

## 机器人端点与访问方式的区别

| 你想要的 | 配在哪里 |
| --- | --- |
| 浏览器访问控制台 | 绑定地址 / 反代 / SSH 隧道（本章） |
| 本机机器人连 OneBot | 「节点配置」建端点 + 在部署侧发布端口，见 [节点配置](onebot-config.md) |
| 让 QQ 桌面可用 | 桌面入口配置 + `/desktop/`（下面一节） |

三者互不替代：控制台密码不能当 OneBot 令牌用，OneBot 令牌也打不开控制台。

## 桌面入口 `/desktop/`

Docker 部署下，QQ 桌面不是「另一个网站」，而是控制台的同源路径。

| 事实 | 说明 |
| --- | --- |
| 路径 | `/desktop/`，由控制台同一端口提供 |
| 暴露端口 | 只有 5099。**不再单独发布 6080** |
| 浏览器侧认证 | 路径限定的 HttpOnly、SameSite=Strict 会话 Cookie；控制台令牌与 VNC 密码都不放进 URL |
| 网关校验 | 桌面 HTTP、脚本、WebSocket 都检查有效控制台会话；初次改密与协议确认不能绕过 |
| Origin 检查 | WebSocket 必须携带与当前主机匹配的 Origin |
| 会话失效 | 退出登录、改密、会话到期后不能继续操作；空闲连接会关闭 |
| 后台 VNC | 只监听回环 `5900`，保留独立密码认证；密码不返回给浏览器 |
| 外部桌面地址 | 「服务 → QQ 桌面」可填外部地址；它由外部服务自己的认证保护，不会自动获得控制台会话 |

也就是说：能打开控制台的人才可能打开桌面；VNC 自己的密码是服务器内部使用的第二道门，不需要你输入。

**为什么不在 URL 里放令牌**：URL 会进浏览器历史、代理日志、Referer 和截图。会话放在 HttpOnly Cookie 里，脚本读不到，代理日志里也没有明文。

## 示例：把内网服务放到 HTTPS 域名后

1. 在 `deploy/.env` 里保持 `BIND_ADDRESS=127.0.0.1`。
2. 在 Nginx 里配置 `https://nowluma.example.invalid` → `127.0.0.1:5099`，包含上面两段 location。
3. 控制台「服务 → 服务监听」里把 `trustProxy` 设为 `1`，保存并重启。
4. 浏览器打开 `https://nowluma.example.invalid`，登录，点「打开 QQ 桌面」。

**预期结果**：地址栏是 HTTPS，页面顶部没有不安全访问提示，桌面能正常打开并操作 QQ。

**失败怎么办**：

| 现象 | 检查 |
| --- | --- |
| 桌面打不开 | 反代是否代理了 `/desktop/`、是否透传 WS 升级头、会话是否有效 |
| 日志不实时 | 是否关闭了 `proxy_buffering` |
| 来源显示成代理 IP | `trustProxy` 没设或设错 |
| 一直提示不安全访问 | 浏览器看到的协议不是 HTTPS（常见于反代终止 TLS 但 `X-Forwarded-Proto` 没传） |
| 502 / 连接被拒 | 后端是否在监听、端口是否与 `deploy/.env` 一致 |

## 端口发布原则

| 端口 | 默认发布到 | 说明 |
| --- | --- | --- |
| 5099 | 宿主回环 | 控制台 + 桌面（同源） |
| 3000 | 宿主回环 | OneBot HTTP |
| 3001 | 宿主回环 | OneBot WebSocket |
| 5900（VNC） | **不发布** | 容器内回环，仅网关访问 |
| 6080 | **不使用** | 旧方案已移除 |

多账号共用监听服务时要给每个账号分配不同端口，并在部署侧发布对应端口。

## 安全提醒

- 非回环地址 + 非 HTTPS 时，页面顶部一直显示不安全访问提示；这不是可以点掉的小事。
- 反向代理不要额外加一层「裸 HTTP 转发到公网」。
- 不要把带 `?token=` 的地址分享出去。
- 只在你自己的受信任网络里使用局域网模式；公共 Wi-Fi 下请用隧道。
