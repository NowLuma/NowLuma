# 访问方式与网络

先确认本机能访问；如需连接远程主机，请用 SSH 转发或 HTTPS。

![服务页中的部署诊断信息](/images/tutorials/deployment-diagnostics.png)

控制台默认只监听本机。个人远程访问可用 SSH 隧道；需要共享入口时，配置 HTTPS 反向代理。

## 三种入口

| 入口                         | 适合                   | 要点                             |
| ---------------------------- | ---------------------- | -------------------------------- |
| 本机 `http://127.0.0.1:5099` | 同一台机器             | 默认绑定 `127.0.0.1`，不经过网络 |
| SSH 隧道                     | 远程服务器             | 只在本机开端口，流量走 SSH       |
| 局域网 / 反向代理            | 受信任网络或已有 HTTPS | 必须有强访问密码；公网必须 TLS   |

安装向导的「仅本机/SSH（推荐）」把绑定地址设为 `127.0.0.1`；「局域网」设为 `0.0.0.0` 并提示 HTTP 未加密。

## SSH 隧道

```bash
ssh -L 5099:127.0.0.1:5099 -L 3001:127.0.0.1:3001 用户名@服务器地址
```

保持窗口打开，再访问 `http://127.0.0.1:5099`。机器人端口按需转发；不要把 5099 直接发布到公网。

## 局域网

- 在「偏好设置 → 服务 → 服务监听」把绑定地址改为 `0.0.0.0`，或安装时选择局域网。
- 只允许可信网段访问；用防火墙限制来源。
- 局域网 HTTP 不加密，密码和会话可能被同一网络的人截获；应配置 TLS 或只在 SSH 隧道内使用。
- 修改监听设置后重启 Nowluma。

## 反向代理

代理必须保留真实 Host、协议头和 WebSocket 升级。示例（先配置 TLS）：

```nginx
location / {
    proxy_pass http://127.0.0.1:5099;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
location /desktop/ {
    proxy_pass http://127.0.0.1:5099;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;
}
```

- 不要移除 `/desktop/` 前缀，也不要代理到旧的 6080。
- 只有位于受信任代理后才把「信任代理 (trust-proxy)」设为 `1`、`loopback` 或明确 IP；无条件信任转发头会让来源判断失效。
- 代理的 Basic Auth 不能替代 Nowluma 访问密码；两层可以并存。

## HTTPS / TLS

- 在「偏好设置 → 服务 → HTTPS / TLS」粘贴有效 PEM 证书与私钥；私钥只写入 `config/key.pem`（0600），不会回显。
- 启用后若证书无法加载，WebUI 启动失败，不会静默降级为 HTTP。
- 也可以由反向代理终止 TLS，再由代理转发到回环 HTTP；此时浏览器到代理是 HTTPS，代理到本机应只在同一主机或受信任网络。
- 证书过期、域名不匹配或链不完整都会导致浏览器拒绝；先在浏览器确认证书有效。

## 桌面认证

Docker 桌面通过 `/desktop/` 同源访问：

- 浏览器使用 HttpOnly、SameSite=Strict 的路径限定 Cookie；控制台令牌或 VNC 密码不进入 URL。
- 网关在服务器侧校验控制台会话；后台 VNC 只监听回环 5900，并保留独立认证，不把密码返回浏览器。
- 退出、改密、会话到期后桌面操作停止；WebSocket 还校验 Origin。
- 要确定「打开 QQ 桌面」是否可用，见[打开 QQ 桌面](qq-connection.md#打开-qq-桌面)。

## 令牌、密码与会话

- 登录后会话存在浏览器；「退出登录」清除当前浏览器的令牌。
- 修改访问密码会让其他设备的会话立即失效；完成修改的当前浏览器会收到轮换后的会话，不需要再次登录。
- [用链接登录](first-run.md#用链接登录)时请妥善保管链接，其中包含访问密码。
- 2FA 开启后还需要一次性验证码或恢复码；恢复码只显示一次。

## 安全恢复

| 情况           | 处理                                                                              |
| -------------- | --------------------------------------------------------------------------------- |
| 忘记访问密码   | 停服务、备份并移走 `config/webui.json`，重启读取新初始密码；会同时清除 2FA 和会话 |
| 丢失 2FA       | 用恢复码登录；没有恢复码时按上面的重置处理                                        |
| 怀疑会话泄露   | 修改访问密码使其他会话失效；检查反向代理与网络访问                                |
| 不安全横幅     | 非回环且非 HTTPS；改用 SSH 或 TLS                                                 |
| 代理后来源错误 | 检查 `trust-proxy` 与代理头，不要盲目信任所有来源                                 |

恢复步骤见[首次启动](first-run.md#忘记密码或丢失-2fa)。重置密码不会删除账号、消息或连接配置，但会删除当前的认证状态。

## 排障

- **打不开**：确认绑定地址、端口、防火墙、隧道和代理；`doctor` 查看容器健康。
- **登录后立即失效**：Cookie 被代理改写、Host 不一致或系统时间偏差；检查代理与时钟。
- **桌面空白**：代理未保留 `/desktop/` 或 WebSocket 升级；检查控制台会话是否有效。
- **混合内容**：HTTPS 页面里请求 HTTP 资源会被浏览器拦截；所有入口统一用 HTTPS 或相对路径。
- **局域网能访问但机器人不能**：机器人端口是否发布、绑定地址与防火墙是否放行；令牌是否正确。
