# 系统设置：控制台

「系统设置」页（`/settings`）把十组设置分成三段：**控制台**（这一章）、**Nowluma**、**平台**（后两段在 [系统设置：Nowluma 与平台](settings-runtime.md)）。

左侧是分组导航，桌面宽度显示三个段标题，手机上是平铺的横向列表。当前页签记在地址的 `?tab=` 里，因此可以直接分享某个设置的链接；默认页签是「外观」。

| 段 | 页签 |
| --- | --- |
| 控制台 | 外观、数据与格式、账号安全 |
| Nowluma | 全局配置、存储管理、通知 |
| 平台 | 服务、高级、开发者、关于 |

## 外观

「外观」只影响**这个浏览器**的显示，保存在界面配置里。改动 400ms 防抖自动保存，失败时右下角提示「外观同步失败」，本地仍然生效。

### 主题

| 控件 | 选项 |
| --- | --- |
| 调色板 | 11 套预设，包含默认的淡紫强调色等 |
| 「显示模式」 | 浅色 / 深色 / 跟随系统 |
| 「深色强度」 | 柔和 / 纯黑（OLED） |

选了固定明暗的调色板（如 Catppuccin 系）时，显示模式和深色强度会变成无效项——这是设计行为，不是故障。

### 强调色

- 预设色 + 自定义取色器。
- 「应用范围」：全局 / 仅侧栏。
- 「侧栏样式」：跟随背景 / 浅色面板 / 强调色。

选到对比度过低的颜色时，本次会话会弹一次「强调色对比度较低」，可以「恢复默认色」或「仍然使用」。它只提醒一次，不会每次改都拦你。

### 背景

| 控件 | 说明 |
| --- | --- |
| 类型 | 无 / 纯色 / 渐变 / 图片 |
| 纯色 | 取色器 |
| 渐变 | 预设渐变 |
| 图片 | 上传壁纸，支持 PNG / JPEG / WebP，最大 5MB；带预览和「移除」 |
| 「遮罩强度」 | 0–1，控制背景被压暗的程度 |
| 「背景模糊」 | 0–40px |

上传的壁纸保存在界面配置里，**不包含**在「高级 → 备份与重置」的导出文件中；换设备要重新上传。

### 排版与界面

| 控件 | 说明 |
| --- | --- |
| 「界面字体」/「等宽字体」 | 预设字体，或选「自定义」手填字体族名 |
| 本机字体列表 | 仅 Chromium 系浏览器支持；读取失败时提示「无法读取本机字体，请检查浏览器权限后重试。」，可以手动输入 |
| 「圆角」 | 界面圆角大小 |
| 「界面缩放」 | 整体缩放滑杆 |
| 「显示密度」 | 舒适 / 紧凑 |

### 主题微调

列出 10 个白名单 CSS 变量，每个都可以单独取色、单独恢复默认，底部有「全部恢复默认」。

这些变量登录页也会收到（只限白名单和颜色值），所以登录页和登录后的观感一致。

### 顶栏

三个开关，对应顶栏的三个可切换元素：「连接状态徽章」「主题切换按钮」「展示模式按钮」。关掉后顶栏更干净，但「登出」始终保留。

### 右键菜单

「自定义右键菜单」开关，控制是否把浏览器的右键菜单替换成控制台自己的菜单。

### 交互与无障碍

| 开关 | 作用 |
| --- | --- |
| 「自定义光标」 | 使用自绘光标 |
| 「性能模式」 | 自动检测（默认）/ 完整效果 / 低性能 / 关闭动效；自动模式只在本机前台持续低帧率时降级，不写回服务器，也不承诺帧率或省电收益 |
| 「减弱动效」 | 降低动画幅度 |
| 「关闭全部动效」 | 完全关闭动画，适合低性能设备或对动效敏感的人 |
| 「高对比模式」 | 提高对比度 |
| 「钉住侧栏展开」 | 只出现在桌面宽度；钉住后侧栏保持展开 |

### 被宿主接管时

如果这个控制台被宿主程序以集成模式接管外观（部署时通过 `NOWLUMA_WEBUI_TARGET` 指定），大部分外观项会被禁用，并显示说明：「外观跟随{宿主}。原有配色、字体和背景已保留，退出集成后恢复；缩放与无障碍设置仍可调整。」

此时仍可调整的是「界面缩放」「自定义光标」「高对比模式」等无障碍项；自定义 CSS 会被保留但暂停应用。

## 数据与格式

| 控件 | 选项 | 影响 |
| --- | --- | --- |
| 「轮询间隔」 | 秒数；`0` 暂停前台轮询 | 系统指标的刷新节奏。QQ 列表、进程、连接状态另有一套节流（取轮询间隔 ×10 与 10 秒的较大值），并优先使用 SSE 推送 |
| 「登录后落地页」 | 从导航项里选 | 下次登录后直接进入的页面 |
| 「时间格式」 | 24 小时制 / 12 小时制（AM/PM） | 界面上时间戳的显示方式，不改变日志本身 |

**示例**：把轮询间隔设成 `0`，顶部资源数字停止更新，但日志和连接状态的 SSE 仍然实时。这适合网络受限或想看静态快照的场景。

保存方式是自动保存到界面配置。轮询间隔只改浏览器行为，不改服务端。

## 账号安全

### 修改访问密码

| 元素 | 说明 |
| --- | --- |
| 入口 | 「访问密码」→「修改密码」 |
| 提示 | 「修改后其他设备的会话将立即失效。」 |
| 成功后 | 显示「已更新（hh:mm:ss）— 其他设备的会话已失效。」 |

密码以加盐 scrypt 哈希保存在程序配置目录的 `webui.json`，不保存明文。

**示例**：改密码 → 另一台已经登录的设备在下次请求时被要求重新登录。预期如此；这也是别人拿到你旧密码后你能不能立即止损的关键。

### 退出登录

「退出登录」会先弹「确认退出登录？」，确认后清除当前会话。

### 双重验证

「双重验证」卡片有两个状态：

| 状态 | 显示内容 | 可做的操作 |
| --- | --- | --- |
| 未开启 | `Authenticator` 一行 + 「开启 2FA」 | 开始绑定 |
| 已开启 | 「已绑定 {标签} · 剩余 {n} 个恢复码」、状态行 | 「恢复码」→「重新生成」、「关闭 2FA」 |

绑定流程：

1. 点「开启 2FA」，出现二维码和可手动复制的一次性密钥。
2. 用验证器应用扫码或手输密钥。
3. 输入当前的 6 位验证码确认。
4. 页面给出一组恢复码，并提示「这些恢复码只显示一次…」。**现在就抄下来并存到安全的地方。**

关闭 2FA 时会提示：「关闭后，只需访问密码即可登录。其他已登录会话会立即失效。」

**示例（恢复码的用法）**：手机丢了 → 登录第二步点「使用恢复码」→ 输入一个 8 位恢复码 → 进入控制台 → 在「双重验证」里重新生成恢复码，或关闭后重新绑定。

**失败怎么办**：

| 现象 | 处理 |
| --- | --- |
| 验证码一直被拒 | 检查设备时间是否自动同步；验证码 30 秒一轮 |
| 恢复码也用完 | 用另一台已登录设备重新生成；都没有则按 [首次启动](first-run.md#7-忘记密码或丢失-2fa) 的恢复步骤处理（会同时清掉 2FA 绑定） |
| 改完密码其他设备掉线 | 预期行为 |

## 这一段的保存与生效

| 设置 | 保存位置 | 生效时机 | 重启？ |
| --- | --- | --- | --- |
| 外观全部子组 | 界面配置 | 立即（防抖自动保存） | 否 |
| 数据与格式 | 界面配置 | 立即 | 否 |
| 访问密码 | `webui.json` | 立即；其他设备会话失效 | 否 |
| 双重验证 | `webui.json` | 立即 | 否 |
| 登出 | 服务端会话 | 立即 | 否 |
