# Nowluma 是什么

先在上方练习中找到「QQ 会话」「机器人连接」和「运行记录」。能区分这三处的职责，就能避免把保存配置误认为消息已经送达。

![示例工作台中的会话与连接状态](/images/tutorials/overview.png)

_图：示例读数用于认识状态，不是你的真实账号状态。_

Nowluma 是运行在你设备上的 QQ 接入程序。它找到已经运行的 QQ 客户端，把账号接到 OneBot v11，再用浏览器控制台管理账号、连接、日志和桌面。

## 组成部分

| 部分       | 做什么                                                              |
| ---------- | ------------------------------------------------------------------- |
| 接入层     | 发现本机 QQ 进程，在你确认后附加原生组件，建立通信管道              |
| 账号内核层 | 为每个真实 QQ 号保存接入内核选择与风险确认                          |
| OneBot 层  | 按账号提供 HTTP 与 WebSocket 端点，转发事件、执行动作               |
| 控制台     | 六个页面：工作台、QQ 会话、机器人连接、运行记录、调试工具、偏好设置 |
| 桌面       | 在浏览器里操作 QQ 登录与客户端弹窗，可选本机或 Docker 桌面          |

QQ 的登录、扫码、验证和自动登录始终由 QQ 自己完成。Nowluma 不索取 QQ 密码，不伪造设备令牌，也不迁移你的 QQ 用户目录。

## 它不做什么

- 不替你登录 QQ，访问密码也不等于 QQ 密码。
- 不因为端点「正常」就保证机器人会回复；那只说明监听或连接成功。
- 不把「保存了配置」说成「已经生效」。
- 不把保留本地数据说成「重启一定免扫码」。
- 不在没有账号本人确认的情况下接入兼容内核。

## 三种不同的保存结果

| 动作                     | 保存方式                       | 什么时候生效                                                 |
| ------------------------ | ------------------------------ | ------------------------------------------------------------ |
| 界面偏好、布局、导航顺序 | 自动保存到界面配置，输入有防抖 | 浏览器里立即生效，跨设备同步；同步失败时保留本地状态并提示   |
| 每账号的机器人连接       | 对话框或「立即保存」写入服务端 | 在线且热重载成功才是「已保存并应用」；否则按提示等到下次连接 |
| 服务级设置               | 点保存后写入，界面明确提示     | 多数需要重启 Nowluma；界面会写出「重启 Nowluma 后生效」      |

典型例子：QQ 账号离线时改 HTTP 端口，保存成功但只显示「已保存，下次连接时应用」；等这个账号真正接入后才使用新端口。只有「已保存并应用」表示服务端已经热重载。

## 四类“连接”

| 说法         | 在哪里看                                 | 含义                                           |
| ------------ | ---------------------------------------- | ---------------------------------------------- |
| 控制台已连接 | 顶栏的连接状态                           | 浏览器会话有效，能读写控制台                   |
| 账号已在线   | QQ 会话的进程卡、工作台的「已登录会话」  | QQ 已登录，账号身份已被本地识别并接入          |
| 端点正常     | 机器人连接的摘要、工作台的「机器人连接」 | 监听中或已连上；机器人程序仍需正确的地址与令牌 |
| 通知已投递   | 工作台的「通知投递」                     | 上下线事件发送到了你选中的通知渠道             |

## 账号内核的选择

接入一个 QQ 号之前，控制台会要求为该真实 UIN 选择接入内核：

- 「兼容内核」使用随包提供的原生组件，需要你主动勾选并确认当前版本的风险说明，未勾选时不能提交。
- 「重写内核」当前显示为「暂不可用」，不能选择，也不会静默回退到兼容内核。
- 选择按账号保存在 `config/kernel-selections.json`，只对这个 UIN 生效。
- 单独保存选择不会接入进程；只有在 QQ 会话里点「加载」或「重新连接」才会附加。
- 换一个 QQ 号、账号身份变化或风险说明版本更新，都要重新确认，不能复制上一个 PID 的确认。

## 状态词

QQ 进程：`可加载`、`加载中`、`等待连接`、`等待登录`、`已在线`、`错误`、`已断开`。

机器人端点：`正常`、`注意`、`异常`、`应用失败`、`未启用`。「应用失败」表示配置已保存，但热重载失败，服务端会尽量恢复旧端点。

## 平台与发行

| 形态         | 要求                                              | 验证状态                                          |
| ------------ | ------------------------------------------------- | ------------------------------------------------- |
| Linux Docker | Docker Engine 与 Compose v2，linux/amd64          | 自动化构建与重建 smoke 已覆盖；真实 QQ 登录不假报 |
| Linux Lite   | Node.js `24.22.1`（24.x）或 `>=26.12.1`           | 启动器与发行布局有检查；原生接入需自己验证        |
| Windows x64  | 自包含 `Nowluma.exe`，内置 Node 24 与 .NET 运行时 | 已构建、未签名，真实账号行为未验证                |
| Docker arm64 | 有构建输入                                        | 未实际验证                                        |

## 数据位置

| 内容                                  | 源码/发行目录 | Docker 卷                           |
| ------------------------------------- | ------------- | ----------------------------------- |
| 控制台密码、2FA、连接、内核选择、外观 | `config/`     | `nowluma_config` → `/app/config`    |
| 账号消息库与媒体                      | `data/`       | `nowluma_data` → `/app/data`        |
| 运行日志                              | `logs/`       | `nowluma_logs` → `/app/logs`        |
| QQ 自己的用户环境                     | 由 QQ 决定    | `nowluma_qq-home` → `/home/nowluma` |
