# Nowluma 是什么

Nowluma 由两部分组成：

1. **接入层**：找到本机正在运行的 QQ 客户端进程，把账号消息以 OneBot v11 形式提供给机器人程序。
2. **控制台**：浏览器里的中文管理界面，包含总览、QQ 连接、节点配置、日志、调试、系统设置六个页面。

QQ 登录始终由 QQ 自己完成。程序不替你登录、不保存 QQ 密码、不伪造设备令牌，也不需要迁移你的 QQ 用户目录。

## 它不做什么

| 常见误解 | 实际情况 |
| --- | --- |
| 控制台会帮我登录 QQ | 不会。扫码、验证、自动登录设置都在 QQ 窗口（或「打开 QQ 桌面」里的 QQ 窗口）完成。 |
| 填了访问密码就等于 QQ 登录 | 不是。访问密码只用来进控制台，和 QQ 账号无关。 |
| 端点显示「正常」就说明机器人能用 | 不是。它只表示服务在监听或连接已建立，见下文状态词表。 |
| 改了一处配置就该立刻生效 | 不一定。多数设置需要「保存」，其中一部分要重启，另一部分要等账号下次连接。 |
| 本地数据留着就一定免扫码 | 不保证。本地凭据保留只能避免因为重建部署而产生新环境，QQ 服务端是否接受会话由 QQ 决定。 |

## 三类“在线/离线”

界面上同一个词在不同位置含义不同，排障时最容易在这里误判。

| 说法 | 出现在哪里 | 真实含义 | 怎么确认 |
| --- | --- | --- | --- |
| 控制台已连接 | 顶栏的连接状态徽章 | 浏览器与控制台的会话还有效 | 徽章恢复后页面不再要求重新登录；会话失效会回到登录页 |
| 账号已在线 | 「QQ 连接」页、总览「在线账号」部件 | 该 QQ 进程已完成登录并被程序识别 | 卡片状态显示「已在线」，并显示 UIN |
| 端点正常 | 「节点配置」的节点卡片、总览「OneBot 连接」部件 | 监听端口在听，或反向连接已建立 | 卡片状态芯片；**仍需**机器人程序填写正确令牌并自行工作 |
| 账号映射离线 | 通知事件 `{event}` | 该账号从在线变为离线（有去抖窗口） | 看 [通知](settings-runtime.md#通知) 的去抖设置 |

## 三种不同的“保存”结果

控制台里有三套彼此独立的持久化方式，混淆它们会得到错误结论。

| 家族 | 存在哪里 | 生效方式 | 失败表现 |
| --- | --- | --- | --- |
| 界面偏好（外观、布局、页面偏好、全局配置、通知） | 程序配置目录的界面配置文件 | 输入后自动保存（有防抖），立即在浏览器生效 | 右下角提示「外观同步失败」等；本地值仍生效，但没落盘 |
| 每个账号的 OneBot 配置 | 该账号的配置文件 | 点「保存」后由服务端返回结果 | 保存状态芯片显示具体失败原因 |
| 服务级设置（监听、TLS、备份恢复、更新） | 程序配置目录 | 点「保存」后提示是否需要重启 | 就地显示错误，并保留原配置 |

只保存过、没有生效的典型提示是「已保存，下次连接时应用」。只有看到「已保存并应用」才表示运行中的端点已经换成新配置。

### 一个具体例子

1. 打开「节点配置」，选一个**当前未在线**的账号，在「HTTP API」里新建一个节点，端口 `3000`。
2. 点「保存」。
3. 预期结果：保存状态芯片显示「已保存，下次连接时应用」。

原因：账号不在线时服务端无法热重载端点。等你回到「QQ 连接」把该账号加载起来，它才会真正监听 3000。

## 状态词表

QQ 进程（「QQ 连接」页卡片）：

| 字样 | 含义 |
| --- | --- |
| 可加载 | 找到 QQ 主进程，尚未接入 |
| 加载中 | 正在向该进程注入接入组件 |
| 等待连接 | 已注入，等待本地管道连上来 |
| 等待登录 | 管道通了，但账号还没登录 |
| 已在线 | 账号已登录并被识别 |
| 错误 | 本次操作失败，卡片会给出错误行 |
| 已断开 | 之前接入过，现在断开了 |

OneBot 端点（节点卡片与总览部件）：

| 字样 | 含义 |
| --- | --- |
| 正常 | HTTP 在监听 / WS 已连接 |
| 注意 | 有可恢复的问题，例如最近一次错误 |
| 异常 | 监听失败或连接失败 |
| 应用失败 | 配置已保存，但热重载失败，服务端尽力恢复了旧端点 |
| 未启用 | 节点存在但被关闭 |

## 平台支持现状

| 场景 | 现状 |
| --- | --- |
| Docker（Linux/amd64） | 安装向导、启动、桌面、重建保留数据都有自动化验证 |
| Docker（arm64） | 有对应构建输入，**没有**实际验证记录，不要当成已测试平台 |
| 原生 Linux 发行包（Lite） | 启动器与检查脚本；需要 Node.js `24.22.1`（24.x）或 `>=26.12.1`，不含 `deploy/install.sh` |
| Windows x64 | 自包含 `Nowluma.exe`，内置 Node；未签名；无需 Docker、Node 或 .NET |

## 数据放在哪里

| 内容 | 原生运行 | Docker |
| --- | --- | --- |
| 控制台密码、2FA、连接、运行与外观设置 | `config/` | 卷 `nowluma_config` → `/app/config` |
| 账号消息库与媒体 | `data/` | 卷 `nowluma_data` → `/app/data` |
| 运行日志 | `logs/` | 卷 `nowluma_logs` → `/app/logs` |
| QQ 自己的用户目录与凭据 | QQ 自己的目录 | 卷 `nowluma_qq-home` → `/home/nowluma` |

源码工作区里还有一个构建输出目录 `dist/`；发行包中它的内容就是程序的根目录。它不是用户数据，升级时被替换。
