# 系统设置：Nowluma 与平台

这一章覆盖「系统设置」里的后七组：**Nowluma**（全局配置、存储管理、通知）和**平台**（服务、高级、开发者、关于）。前两组见 [系统设置：控制台](settings-console.md)。

## 全局配置

影响所有账号的运行时参数。改动 500ms 防抖自动保存，无需点按钮。

| 卡片 | 字段 | 说明 |
| --- | --- | --- |
| `rkey` 回退服务器 | URL 行列表，可增删 | 留空关闭；建议使用自建服务。接口返回 `{ group_rkey, private_rkey, expired_time }`；只接受 HTTP(S)；无效项被服务端丢弃并提示「已保存，无效项已忽略」 |
| 视频上传连接数 | `1` / `2` / `3` / `4` | `1 路（默认）`；并发越高对带宽和对方接口压力越大 |
| 音乐签名服务 URL | 单个 URL | 留空使用内置默认 |

服务端默认值：回退服务器为空数组、音乐签名服务为空、视频上传并发为 1。

**示例**：要接自己的 `rkey` 服务，先在自己的域名上实现上面那个返回结构（文档里用 `https://rkey.example.invalid/` 作占位），粘进列表，等右下角出现保存成功提示。**预期结果**：列表里保留一条合法 URL；如果填了 `ftp://` 之类，会被丢弃并提示无效项已忽略。

## 存储管理

### 存储概览

四个数字：受管数据总量、日志、账号数据库、传输临时数据。

下方是日志容量进度条，显示 `{已用} / {上限}`、`{n} 个文件`、`{n} 个活动文件`、`丢弃 {n} 行磁盘日志`，以及上次清理（`lastCleanup`）的摘要。

### 日志策略

| 字段 | 说明 |
| --- | --- |
| 「日志总量上限（MB）」 | 超过后按策略淘汰 |
| 「保留天数」 | `0` 表示只按大小淘汰，不按时间 |
| 「按账号额外写入日志」 | 给每个账号单独记日志文件 |

改动后点「保存并应用」，立即生效并返回刷新后的快照。

字段被环境变量锁定时会显示「环境变量锁定」徽章并禁止编辑——这是有意的，配置文件不该和环境变量互相打架。

### 全局数据清理

两行：日志、文件传输临时数据。每行显示大小与活动数量，点清理会弹「确认清理」。

### 账号数据

每个账号一张卡片，分三类，界面给出的说明是：

| 类别 | 包含 |
| --- | --- |
| 消息历史 | OneBot 消息与回复索引 |
| 媒体索引 | 图片、语音与视频的元数据 |
| 表情回应 | 群消息表情回应记录 |

可以按分类清理单个账号，也可以用底部的「全部账号」块：

- 必须**所有账号都离线**才能执行。
- 需要手动输入确认短语 `清理全部账号`。
- 执行前会再弹一次「确认清理」。

**这些操作删除的是文件，不可撤销。** 需要保留时先做备份，见 [数据、备份与更新](data-backup.md)。

## 通知

当账号离线/恢复时，往你配置的渠道发消息。

### 去抖窗口

「去抖窗口（秒）」范围 0–3600，默认 30。说明文字是：下线持续超过此时长才通知，恢复时再通知；`0` 表示立即通知。

这个窗口的意义：程序重启或网络抖动会让账号短暂掉线，窗口设成 30 秒可以避免半夜被叫起来。

### 渠道

| 控件 | 说明 |
| --- | --- |
| 「新增渠道」/「创建第一个」 | 打开渠道对话框 |
| 启用开关 | 逐渠道开关，关闭的渠道不会触发 |
| 「测试发送」 | 立即发一条测试消息；会先把挂起的编辑保存掉 |
| 「编辑」 | 修改渠道 |
| 「删除」 | 移除渠道 |

渠道对话框字段：

| 类型 | 字段 |
| --- | --- |
| 公共 | 类型（`Webhook` / `邮件`）、「渠道 ID」、「显示名」 |
| Webhook | 「Webhook URL」、「请求头」行、「Body 模板」 |
| 邮件 | 「SMTP 主机」、「端口」、「SMTP 用户名」、「SMTP 密码」、「隐式 TLS」、「发件人」、「收件人」、「主题模板」、「正文模板」 |

正文模板以 `<` 开头时按 HTML 发送，否则按纯文本。

模板变量：`{uin}`、`{nickname}`、`{event}`、`{time}`、`{status}`、`{pid}`、`{error}`。

**示例**：建一个 Webhook 渠道，URL 填 `https://hooks.example.invalid/nowluma`，Body 模板：

```json
{"text":"{nickname}({uin}) {event} at {time}"}
```

保存后点「测试发送」。预期结果：你的接收端收到一条测试消息；失败时就地显示错误，不会假装成功。

**注意**：Webhook 地址、SMTP 密码都算凭据，会写进配置文件，也可能被包含在「导出时包含敏感配置」的备份里。不要把渠道配置截图发到公开渠道。

**每个账号是否通知**在 [节点配置](onebot-config.md#通知选择opt-in) 的「通用设置」里选，不在这里。

## 服务

页面顶部有一条常驻提示：「监听相关设置（端口 / 绑定地址 / HTTPS）属服务级配置，保存后需重启 Nowluma 才生效；本机无自动重启。」

记住这句话：**控制台没有一键重启监听的能力**，保存后你要自己重启服务（Docker 用 `bash deploy/manage.sh restart`，原生则重启程序）。

### 服务监听

| 字段 | 说明 |
| --- | --- |
| 「端口」 | 控制台监听端口，默认 `5099` |
| 「绑定地址」 | 快捷按钮「仅本机」= `127.0.0.1`、「所有网卡」= `0.0.0.0`；选所有网卡会警告：允许局域网访问，建议同时启用 HTTPS 并设置强访问凭据 |
| 「信任代理 (trust-proxy)」 | 留空 = 只信任 socket 对端；`1` = 信任反向代理转发的头 |
| 「自动连接已打开的 QQ」 | 保存后重启生效；**这不是 QQ 自动登录** |
| 「保存」 | 提交 |

被环境变量覆盖的字段显示「被环境变量覆盖」并禁用编辑。

只有在确实有受信任反向代理时才设置 `trustProxy`；无条件信任公网请求的转发头会让来源判断失效。

### QQ 桌面（noVNC）

| 字段 | 说明 |
| --- | --- |
| 「noVNC 端口」 | 桌面入口使用的端口 |
| 「桌面地址（可选）」 | 外部桌面地址 |
| 「保存入口设置」 | 只改入口，不改桌面服务的监听端口 |
| 「打开 QQ 桌面」 | 打开入口 |

端口为 0 且地址留空时，入口会被隐藏。提示文字说明：此设置只改变入口，不改变桌面服务监听端口，也不传递控制台令牌或 QQ 密码。

Docker 部署下桌面通过同源 `/desktop/` 访问，复用控制台会话，**不需要单独的 VNC 密码**；`bash deploy/manage.sh vnc-password` 会直接告诉你这一点。后台 VNC 仍只监听回环并保留自己的认证。

### HTTPS / TLS

| 控件 | 说明 |
| --- | --- |
| 「启用 HTTPS」 | 开关 |
| 证书 PEM / 私钥 PEM | 粘贴后点「保存证书」 |
| 已安装状态 | 显示「证书与私钥已安装（出于安全不回显，未改变。）」，提供「更改证书」「删除证书」 |

行为约定：

- 无效证书会被拒绝，不会「凑合着用」。
- TLS 配置错误会导致启动失败，而不是静默降级成 HTTP。
- 删除证书需要确认（「删除 TLS 证书？」）；如果 HTTPS 仍然开启，下次启动可能失败。

### 配置备份与恢复

| 控件 | 说明 |
| --- | --- |
| 「导出时包含敏感配置」 | 勾选后备份包含凭据；旁边有红色警告列明包含：控制台会话状态、TLS 私钥、通知 URL、OneBot 令牌 |
| 「导出备份」 | 下载备份文件 |
| 「选择备份文件并恢复」 | 导入；确认框「恢复配置备份？」 |
| 恢复结果 | 「已恢复 N 项」「跳过 N 项（敏感配置，含 OneBot 配置）」「兼容转换 N 项」「重启后生效」 |

恢复是**覆盖式**的：会替换现有配置，且通常需要重启才完全生效。没有备份就恢复，等于把当前配置丢掉。

### 运行环境与保存位置

诊断卡片显示：

- 程序工作目录、当前服务 HOME、程序配置、消息与媒体、运行日志。
- Linux 上额外显示「Linux 默认 QQ 配置」。
- 每个目录后面有「可写」或「未创建或不可写」徽章。
- 按钮「复制诊断」（不含凭据）、「刷新状态」。

旁边的说明强调两件事：数据卷必须整体保留（包括 QQ 的整个 HOME），以及**不要用 `down -v`**。

## 高级

### 自定义 CSS

| 控件 | 说明 |
| --- | --- |
| 文本框 | 最多 50000 字符 |
| 片段按钮 | 「侧栏字号」「卡片毛玻璃」「隐藏滚动条」「加粗标题」「紧凑卡片」各插入一段 |
| 校验 | 失去焦点时检查：花括号不配对、没有任何规则、解析失败都会给警告，但**从不阻止保存** |
| 「清空」 | 清空全部自定义 CSS |

- 自定义 CSS 只在登录后应用，登录页不受影响。
- 宿主接管外观时它会被保留但暂停使用。
- 写坏到看不见界面时，在地址后加 `?safe-mode=1` 打开控制台：这个参数会跳过自定义 CSS，让你能进去改回来。

**示例**：粘贴一条让侧栏字号变小的规则 → 保存 → 提示可能显示警告但仍保存成功 → 界面立刻变化。如果整页错乱，用 `https://你的地址/?safe-mode=1` 进入，删掉规则再保存。

### 备份与重置

| 控件 | 说明 |
| --- | --- |
| 「导出」 | 下载 `nowluma-ui-config.json`（外观、布局、页面偏好、自定义 CSS） |
| 「导入」 | 选择 ≤256KB 的 JSON，确认「导入并覆盖界面配置？」后整页刷新 |
| 「重置全部」 | 确认「重置全部界面配置」，提示「此操作不可逆。」 |

注意范围：这只是**界面**配置。背景图片不在导出文件里，需要重新上传；账号、连接、消息数据都不在里面（那些在 [服务 → 配置备份](settings-runtime.md#配置备份与恢复) 与 [数据、备份与更新](data-backup.md)）。

## 开发者

| 卡片 | 操作 | 影响 |
| --- | --- | --- |
| 「界面测试」→「首次使用引导」 | 「重新进入」 | 以演练方式重放引导两步，不修改协议确认记录，也不改真实访问密码 |
| 「界面测试」→「崩溃界面」 | 「触发崩溃」 | 主动抛异常，进入崩溃界面；在崩溃界面点「重试」即可返回 |

这两项与部署环境无关，始终可见。它们只用于验证界面路径，不产生业务副作用。

## 关于

- 品牌区：产品名、版本号、副标题、一句话简介。
- 「软件更新」：当前版本、「检查更新」按钮，以及几种状态——「已是最新」「发现新版本」「检查已关闭」「无法检查」；「重新检查」；发布说明与「发布说明」链接。
- 「下载来源模式」：`自动切换` / `GitHub 直连` / `指定镜像`；镜像列表一行一个；「测试」逐条给出结果；「仅保留可用镜像」；保存。
- 更新安装器：下载并重启；就绪时显示「更新已就绪 · 重启后生效」，重启前会再确认，下载中每秒轮询一次进度。
- 支持卡：「去 GitHub 点 Star」，以及仓库、发行版、反馈问题三个链接。

更新相关的诚实说明：

- 「检查已关闭」表示这个构建没有可用的更新源，不是网络错误。
- 从源码运行或没有发行信息时可能显示「无法检查」。
- 重启会中断所有已连接的机器人，选一个没人用的时间。
- 更新源镜像由你自己填写；本文档不推荐也不验证任何第三方镜像。

## 这一段的保存与生效总表

| 设置 | 保存方式 | 生效时机 | 重启？ |
| --- | --- | --- | --- |
| 全局配置 | 自动（500ms 防抖） | 立即 | 否 |
| 日志策略 | 「保存并应用」 | 立即（返回刷新后的快照） | 否 |
| 数据清理 | 确认后执行 | 立即，不可撤销 | 否 |
| 通知渠道 | 自动（350ms 防抖） | 立即 | 否 |
| 服务监听 / 桌面入口 / 自动接入 | 「保存」 | 需要的场合 `restartRequiredToApply` | **是** |
| TLS 证书 | 「保存证书」/「删除证书」 | 下次启动加载 | **是** |
| 配置备份恢复 | 导入 | 部分立即，其余重启后 | 通常需要 |
| 自定义 CSS | 失焦保存 | 立即 | 否 |
| 界面配置备份/重置 | 导入/重置 | 导入后整页刷新 | 否 |
| 更新下载 | 「下载」 | 「重启后生效」 | **是** |

## 危险操作一览

| 操作 | 确认文案 | 后果 |
| --- | --- | --- |
| 清理日志 / 临时数据 / 单账号分类 / 全部账号 | 「确认清理」+ 手动输入 `清理全部账号` | 删除文件，不可撤销 |
| 删除 TLS 证书 | 「删除 TLS 证书？」 | 若仍开 HTTPS，下次可能启动失败 |
| 恢复备份 | 「恢复配置备份？」 | 覆盖当前配置，可能含凭据 |
| 导入界面配置 | 「导入并覆盖界面配置？」 | 覆盖外观/布局/页面偏好/CSS 并刷新 |
| 重置全部界面配置 | 「重置全部界面配置」+「不可逆」 | 丢失全部界面定制 |
| 重启应用（更新后） | 重启确认 | 中断所有已连接机器人 |
