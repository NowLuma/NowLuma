# 数据、备份与更新

完整备份应同时保留 Nowluma 的数据和 QQ 的用户环境，两者分开存放。

![存储管理中的日志、临时传输与账号数据库](/images/tutorials/storage.png)

![服务设置中的备份与恢复入口](/images/tutorials/backup.png)

## 数据放在哪里

| 内容                                           | 原生          | Docker 卷 → 容器路径                |
| ---------------------------------------------- | ------------- | ----------------------------------- |
| 控制台密码/2FA、连接、内核选择、运行与外观设置 | `config/`     | `nowluma_config` → `/app/config`    |
| 账号消息库、媒体                               | `data/`       | `nowluma_data` → `/app/data`        |
| 运行日志                                       | `logs/`       | `nowluma_logs` → `/app/logs`        |
| QQ 用户环境、凭据、自动登录、机器 ID           | QQ 自己的目录 | `nowluma_qq-home` → `/home/nowluma` |

`dist/` 是构建产物，升级会替换；不要把自己的文件放在里面。内核选择在 `config/kernel-selections.json`，按真实 UIN 保存，不要手工复制到另一个账号。

## 备份

停服务后再复制，避免 SQLite 与 WAL 正在写入：

```bash
nowluma stop
```

旧安装没有 `nowluma` 命令时，用 `bash deploy/manage.sh stop`。

Docker 至少备份四个卷；原生方式复制 `config/`、`data/`、`logs/`，以及 QQ 自己的用户目录（如果需要保留登录状态）。备份应加密并限制访问，因为里面可能包含令牌、会话和聊天数据。

再启动：

```bash
nowluma start
```

备份不是导出聊天记录：消息库是运行数据，恢复时按原目录放回；不要把单个数据库文件热拷贝到正在运行的服务上。

## 恢复

1. 停止服务。
2. 保留当前目录或卷的副本，便于回退。
3. 按原结构恢复 `config/`、`data/`、`logs/`；QQ HOME 只在确实需要恢复登录状态时替换。
4. 启动并检查登录、账号列表、连接和日志。
5. 如果配置损坏，程序会报错并保留原文件；不要用默认值覆盖，也不要静默删除。

打开「偏好设置 → 服务 → 服务配置备份」，点「导出备份」。默认导出外观、服务设置与证书，不包含消息数据库。打开「包含敏感配置」可一并导出账号内核选择、通知渠道与 OneBot 配置。请加密保管备份，对外仅提供脱敏后的片段；备份可能包含会话、私钥、令牌或聊天记录。

恢复时点「选择备份文件」，阅读覆盖确认。只在需要恢复相应内容时打开「恢复敏感配置」。格式、UIN 与确认值必须有效；旧风险版本或重写选择会保留，但不会自动授权。旧备份没有内核选择仍可使用。恢复成功后重启 Nowluma 以应用配置；只迁移界面布局时，可在「高级」单独导出或导入界面配置。

## 清理

- **日志**：在「存储管理」设置总量上限与保留天数；保存后立即应用。清理临时数据会跳过正在传输的项目。
- **账号数据库**：只清理所选账号的消息历史、媒体索引或表情回应；账号在线时不能清理；全部账号清理要求所有账号离线并输入确认短语。
- **QQ HOME**：不要为了“清理”删除整个 HOME；这会丢登录状态、机器 ID 和 QQ 设置。
- **未使用的连接与账号记录**：先在界面删除对应项，再按需清理数据库；不要直接编辑 JSON。

删除不可撤销。执行前先确认备份可读。

## QQ 的持久化与手动验证

Docker 必须保留**完整** HOME 卷，而不只是 `login.db`。程序固定 UID/GID 1000，`XDG_CONFIG_HOME=/home/nowluma/.config`，机器 ID 在 HOME 中首次生成并复用。

验证步骤：

1. 在 QQ 窗口完成扫码，勾选 QQ 自己的自动登录设置。
2. `nowluma restart`。
3. 打开 QQ 桌面，确认 QQ 是否自动恢复登录；不要只看控制台健康状态。
4. 再 `nowluma stop`、`nowluma start`，或重新创建容器，确认卷仍被复用。

如果 QQ 服务端让会话过期或要求验证，请在 QQ 窗口操作。升级时把原生 QQ 的用户目录保留在原位。

## 升级

- Docker：先停服务并备份，再用 `nowluma update` 重新应用已保存镜像，或用 `nowluma update 2.5.1` 切换到显式版本；源码部署更新源码后运行 `nowluma start`。它们都复用现有卷。`docker compose down -v` 会删除命名数据卷和 QQ HOME。
- 旧安装没有 `nowluma` 时，继续使用对应的 `bash deploy/manage.sh` 命令，或重跑安装命令并选择原安装目录。
- 原生：替换发行目录中的程序文件，保留 `config/`、`data/`、`logs/` 与 QQ 目录。
- 数据库结构升级由程序自行迁移；迁移期间界面会显示账号不可用或后台迁移状态，不要重复启动多个实例。
- 升级后检查账号、连接、内核选择与外观是否仍在；内核选择按 UIN 保留，但账号变化仍要重新确认。

## 更新器

「关于」提供检查与安装更新。更新来源可选自动、GitHub 直连或指定镜像；自动模式先试 GitHub，再按候选顺序切换。

更新通道按 SemVer 比较：预发行运行时可以发现并下载后续预发行版（例如 rc.2 → rc.10）与稳定版；稳定版运行时只接受稳定版。下载与重启仍需你显式确认；Docker 部署用 `nowluma update` 应用已保存版本或显式版本。已经发布的 rc.2 不会追溯获得新代码，但能在 2.5.1 正式发布后看到并下载该稳定版。

镜像站可以转发发行包，但安装与升级的校验值必须能从官方 GitHub 发行页的 `SHA256SUMS`（或官方发行元数据）获得；只信镜像自己提供的校验值不足以证明来源。没有校验值或来源不明的包不要安装。

发行资产：

| 资产                                       | 用途                                                          |
| ------------------------------------------ | ------------------------------------------------------------- |
| `Nowluma-v<version>-linux-x64-lite.tar.gz` | Linux x64 Lite 发行包，供运行时更新                           |
| `Nowluma-v<version>-win-x64-lite.zip`      | Windows 运行时更新归档，不内置 Node                           |
| `Nowluma-win32-x64-<version>.exe`          | Windows 一键启动器，自带 Node 24 与 .NET 自包含运行时，未签名 |
| `SHA256SUMS`                               | 全部发行文件的校验值                                          |

更新包会保留 `LICENSE`、`LICENSING.md`、`EULA.md` 与 `PRIVACY.md`。下载完成后点「重启并更新」；连接会短暂断开，配置与数据保留。没有校验值或来源不明的包不要安装。
