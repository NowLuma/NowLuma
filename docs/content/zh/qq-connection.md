# QQ 会话

在上方练习为示例账号选择内核，接入后再卸载。

![QQ 会话页中已识别的示例进程](/images/tutorials/qq-session.png)

![按账号选择接入内核且风险确认未勾选](/images/tutorials/account-kernel.png)

打开「QQ 会话」（`/processes`）可查找正在运行的 QQ，接入所选账号，刷新管道或卸载。

## 页面结构

| 区域     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 页头     | 「刷新」；「打开 QQ 桌面」仅在服务器实际提供同源桌面时出现   |
| 排序     | 「PID」「名称」「状态」；只有一个进程时不显示                |
| 进程列表 | 头像或占位图标、名称、状态徽章、`PID … · QQ …`、路径与错误行 |
| 进程详情 | 进程、账号、接入状态、会话连接、可选路径与错误               |
| 操作     | 「加载」或「卸载」，以及条件出现的「刷新管道」               |

桌面宽度是列表加详情；窄屏先在列表选一个，再看详情。排序偏好会保存，操作始终只作用于当前选中的 PID。

## 进程状态

| 状态     | 含义                      | 可以做什么           |
| -------- | ------------------------- | -------------------- |
| 可加载   | 找到 QQ 主进程，尚未接入  | 「加载」             |
| 加载中   | 正在附加原生组件          | 等待                 |
| 等待连接 | 已附加，管道尚未连上      | 必要时「刷新管道」   |
| 等待登录 | 管道已连，QQ 账号尚未登录 | 在 QQ 窗口登录       |
| 已在线   | 已登录并识别到真实账号    | 配置机器人连接       |
| 错误     | 接入或连接失败            | 看错误行，重试或刷新 |
| 已断开   | 之前的连接断开            | 「刷新管道」重连     |

「刷新管道」的提示是「刷新管道状态 / 重连」。它只重连已有接入，不会替你重新确认内核。

## 第一步：让 QQ 出现

在运行 Nowluma 的设备上打开 QQ 并完成登录。服务器实际提供同源桌面时，可以用「打开 QQ 桌面」进入容器里的图形 QQ；本机原生部署直接使用桌面上的 QQ。Windows 原生即使配置了 VNC 地址，也不会显示这个入口。

点「刷新」重新读取。如果列表仍为空，页面显示「未检测到可加载 QQ 主进程」和「启动 QQ 后刷新」。

## 接入一个账号

1. 在列表里选中目标进程。
2. 点「加载」开始接入。
3. 首次选择内核或风险说明更新时，在「选择接入内核」中为当前账号确认后继续。
4. 状态依次变为「加载中」→「等待连接」→「等待登录」→「已在线」。如果 QQ 还没登录，会停在「等待登录」；在 QQ 窗口完成扫码或密码登录，再点「刷新」。

**预期结果**：详情显示 `PID … · QQ 你的UIN`，接入状态「Nowluma 已加载」，会话连接「已建立连接」。

### 选择接入内核

对话框标题「选择接入内核」，描述是「昵称 · QQ UIN」，风险说明标明「风险说明版本 … · 仅对 QQ … 生效」。有两个选项：

| 选项     | 现状         | 说明                                               |
| -------- | ------------ | -------------------------------------------------- |
| 兼容内核 | 「可选择」   | 使用随包提供的原生组件；必须主动勾选风险确认       |
| 重写内核 | 「暂不可用」 | 等待平台验证 |

先选「兼容内核」，再勾选「我已阅读并主动确认此账号的兼容内核使用与法律风险」，最后点「确认并接入」。内核选项和确认框默认均未选中。提交中显示「保存中…」；失败原因留在对话框内。

风险说明涵盖账号、数据安全和法律风险。

每个 QQ 号在 `config/kernel-selections.json` 中保存自己的内核选择。

在识别账号或选择内核时点「卸载」，会取消待执行的接入。已发出的保存请求会先结束。要再次接入，请点「加载」。

### 保存内核后的接入方式 {#保存选择不等于接入}

刚为账号确认内核后，请回到「QQ 会话」点「加载」完成首次接入。

启用「自动连接已打开的 QQ」后，已有当前版本兼容内核确认的账号可在 QQ 登录并识别出 UIN 时自动接入。

### 账号变化

- 在 QQ 窗口登录，等控制台识别出 QQ 号，再选择内核。
- 切换 QQ 账号后，为新的 QQ 号选择内核并确认风险。
- 本机账号与通道账号不一致时，进程详情会显示接入失败原因。
- 自动接入、管道重连和命令行启动也按当前 QQ 号检查内核确认。

## 卸载

点「卸载」，再确认「确认卸载 Nowluma？」。卸载会解除当前进程的接入，可能断开会话；账号数据和连接配置会保留。

**卸载后，该 PID 保持手动停止。** 点「加载」可恢复接入。进程退出后再次启动，按新会话处理。

**预期结果**：状态回到「可加载」，详情显示「尚未加载」。如果卸载失败，按提示重启 QQ。

## 刷新管道

进程已接入但显示「已断开」时，点「刷新管道」重连通信通道，沿用当前内核选择。

如果刷新后仍停在「等待连接」，先看下方错误和[运行记录](logs.md)；Linux Docker 无法附加时通常要检查 `SYS_PTRACE`，Windows 可能提示完整性级别。

## 空状态与错误

| 现象               | 界面                                    | 处理                             |
| ------------------ | --------------------------------------- | -------------------------------- |
| 没有进程           | 「未检测到可加载 QQ 主进程」            | 打开并登录 QQ，点「刷新」        |
| 读取失败           | 错误面板与「重试」                      | 修复服务或权限后重试             |
| 读取失败但有旧数据 | 「…；当前显示上次成功读取的进程状态。」 | 处理读取错误后刷新，查看最新状态 |
| 详情丢失           | 「进程 … 已不在列表中」                 | 从列表重新选择目标进程           |
| 接入失败           | 错误行与「重试接入」                    | 按错误修权限、登录或组件问题     |

## 打开 QQ 桌面

点「打开 QQ 桌面」，可在浏览器里使用 QQ。入口使用同源 `/desktop/`，只有 Linux 服务端应用了桌面网关才会显示，与浏览器所在的平台无关。只填 VNC 地址不会开启入口。

使用当前控制台会话即可进入，无需另填 VNC 密码。网关配置见[桌面认证](access-network.md#桌面认证)，重启后的登录验证见 [QQ 的持久化](data-backup.md#qq-的持久化与手动验证)。

## 保存与重启

| 动作                | 是否持久化                                      | 生效时间                                                               |
| ------------------- | ----------------------------------------------- | ---------------------------------------------------------------------- |
| 加载 / 卸载         | 否                                              | 立即                                                                   |
| 内核选择与风险确认  | 是，按 UIN 写入 `config/kernel-selections.json` | 下次接入该账号时仍然有效                                               |
| 自动连接已打开的 QQ | 是，服务级设置                                  | 重启 Nowluma 后；已有当前内核确认的 UIN 可在 QQ 登录身份出现后自动接入 |
| 排序                | 是，页面偏好                                    | 立即                                                                   |
| 打开 QQ 桌面        | 否                                              | 当前会话                                                               |

## 排障

- **列表没有 QQ**：确认 QQ 在同一台设备或同一容器；Docker 需要 `/proc` 与 `SYS_PTRACE`；权限不足时看运行记录。
- **一直加载中**：检查原生组件是否可执行、平台是否匹配；不要反复点，等错误出现。
- **等待连接**：先「刷新管道」；仍失败时看端口、权限和日志。
- **等待登录**：在 QQ 窗口完成登录，再刷新状态。
- **卸载后没有自动回来**：这是手动停止；点「加载」才会重新接入。
- **已在线但机器人收不到消息**：去[机器人连接](onebot-config.md)检查端点和令牌。
- **切换账号后要求重新确认**：这是按 UIN 隔离的预期行为，不能复用旧确认。
- **重写内核不可选**：请使用兼容内核，下一步见[路线图](planned.md#重写内核)。
