# Console design contract

- **Stable content:** warm paper/ink tokens, quiet borders and stationary reading surfaces form the base. Business rows and document actions do not lift or scale. Existing routes, account selection, confirmations, errors, loading states and saved layouts remain functional; decorative layers never replace business content.
- **Selective glass:** theme controls, compact top-bar actions, log search and short menus may use `GlassMaterial`. Its non-interactive backdrop layer sits behind unfiltered labels and focus indicators. Geometry is bounded to 768 × 480 CSS pixels; displacement rasters are at most 256 pixels on their longest side and are regenerated on relevant changes, not in a continuous render loop.
- **Renderer truth:** `refracted` means an SVG displacement map was installed for a Chromium-family user agent with CSS backdrop URL support, not that a browser pixel test passed. Safari/Firefox, unsupported or oversized surfaces and rasterization failures use `frosted`; high contrast/reduced transparency use opaque `solid`. CSS further removes backdrop filters under reduced/disabled motion. Host-managed appearance hides the material and retains its own surface rules. Browser optical acceptance remains separate from unit tests.
- **Bounded line art:** the decorative N field contains 108 vertical strokes, quantized to 1/2/3/4 px, in small chrome regions only. The login field alone opts into a continuous ±2 px, 24-second drift. The existing device-local `nowluma_login_fx` preference and pre-auth “界面有点卡顿” switch pause that drift without changing server appearance preferences. Application reduced/disabled motion and the OS reduced-motion preference always stop drift and costly backdrop filtering.
- **Accessibility and ownership:** real labels, keyboard controls, focus rings, mascot/account imagery and failure feedback stay visible. Named palettes, custom accents/backgrounds, density, UI scale, OLED and host appearance keep their existing ownership. No performance-mode schema or auto-FPS integration is introduced here.

Validation is frontend typecheck, lint, focused optics/material/line-field/login/logs/top-bar/process regression tests, the full frontend suite and production build. Real Chromium refraction, Safari/Firefox fallback, responsive keyboard/screen-reader behavior and device FPS require independent browser validation before acceptance.
