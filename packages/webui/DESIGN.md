# Console design contract

- **Session → connection → results:** overview leads with the selected QQ session and the existing `nextStep` action, followed by saved instruments and reading widgets. Locally recognized identity is not proof of login, and an available endpoint is not proof of a robot reply. Loading, errors, explicit PID selection and account isolation retain their existing owners. The overview calls the shared guarded load directly; it does not add a second kernel choice or confirmation. An optional `manualStopped` flag suppresses idle reattachment prompts, never errors or in-flight work. A stopped workflow clears its transient dialogs.
- **One primary navigation:** the persistent dock owns the six canonical routes. Its saved order/visibility and pinned routes remain intact. The session menu opens **工作区管理** for keyboard/drag reordering, visibility, navigation explanations, hidden-page access, card editing and updates. Management does not repeat the visible route list. Closing it restores focus to the session trigger; entering kiosk closes it without resetting the layout.
- **Stable content:** paper/ink tokens, quiet borders and stationary reading surfaces form the base. Business rows and document actions do not lift or scale. Widget IDs, coordinates, visibility and configuration are unchanged; the existing catalogue remains the sole default source. Account rows offer explicit account-aware connection shortcuts. Decorative layers never replace business content, error details or focus indicators.
- **Optical chrome:** `GlassMaterial` stays behind unfiltered labels and focus rings. `GlassSurface` is the shared bounded composition for action, navigation, search and menu surfaces. Glass refracts real page content, not an exposed artificial stripe scene. Geometry is bounded to 768 × 480 CSS pixels of area, with a 256-pixel maximum raster side. At most 16 geometry rasters are cached across reopened surfaces; resize/preferences coalesce into one update, never a continuous canvas/filter loop. Local press, selection, menu and edge-glint responses use existing Motion/CSS transitions. Low mode keeps short responses and a polished frosted edge.
- **Renderer truth:** `refracted` means SVG displacement was installed for Chromium-family CSS backdrop URL support, not that a pixel test passed. Safari/Firefox, unsupported/oversized surfaces and raster failures use `frosted`; high contrast/reduced transparency use opaque `solid`. Host-managed appearance hides the material and retains its surface rules. Static refraction may remain under reduced motion: optical displacement is not an animation. No free-GPU-cost or measured-animation-quality claim follows from unit tests or a screenshot.
- **Quantized identity:** the reusable 48-stroke signature uses the canonical SVG as an alpha mask, fixed at 1/2/3/4 CSS px; the master mark is not redrawn. Login leads with a composed session→stream→results line study and a small signature, not an oversized N. **显示效果** reuses device-local `nowluma_login_fx` values: `0` keeps a static study without the optical pane; `1` adds the pane and a calm 10-second stream glide when motion and the rendering budget allow it. The selection and effective static/frosted state are visible immediately. It never forces high performance or writes server appearance. The separate theme button retains the existing local cache and token-guarded persistence owner.
- **Keyboard editing:** focused desktop handles use Arrow movement, Shift+Arrow resizing and Delete hiding through the existing GridStack/change writer. Bounds/minimum dimensions and durable widget config are retained; hiding restores focus to a surviving handle or the gallery. Mobile edit handles use ArrowUp/Down through the original one-dimensional order writer, with unchanged IDs/visibility/shared config. Pointer behavior and the separate mobile layout remain intact.
- **Performance and accessibility:** OS/manual reduced or disabled motion stops decorative movement; low performance stops lattice drift without rewriting the saved preference. The existing automatic sampler, session-only low latch, explicit performance modes and hidden-tab handling remain unchanged. Controls retain labels, keyboard equivalents, 44px targets and visible focus. Neutral/light/dark and named palettes, custom accents/backgrounds, density, UI scale, OLED and host appearance retain their existing ownership.

Validation is frontend typecheck/lint, effect-control and guarded-flow interactions, material cache/observer lifecycle, canonical line identity, navigation management and persistence regressions, the full frontend suite, production build and demo build. Real Chromium refraction, Safari/Firefox fallback, 375/768/1440 layouts, keyboard/screen-reader behavior and frame continuity require parent-owned browser acceptance. These checks do not prove QQ delivery, robot replies or account login.
